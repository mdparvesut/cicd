## 🔑 Part 1: Generate SSH Key Pair

### On Linux/macOS/WSL:

Open terminal and run:

```bash
# Generate a 4096-bit RSA key
ssh-keygen -t rsa -b 4096 -C "your.email@ut.ee"

# When prompted for file location, press Enter (use default):
# /home/yourusername/.ssh/id_rsa

# When prompted for passphrase:
# You can leave it empty (just press Enter twice) for simplicity
# OR set a strong passphrase for extra security
```

**What this creates:**
- `~/.ssh/id_rsa` - **Private key** (KEEP SECRET!)
- `~/.ssh/id_rsa.pub` - **Public key** (safe to share)

### View your public key:

```bash
cat ~/.ssh/id_rsa.pub
```

**Copy the entire output** - it looks like:
```
ssh-rsa AAAAB3NzaC1yc2EAAAADAQABAAACAQDZx... your.email@ut.ee
```

## 🖥️ Part 3: Create Virtual Machine in ETAIS

### Step 1: Check Available DNS Name

Before creating the VM, let's check if your desired name is available:

```bash
# Test if the name is available
# Replace "reddit-clone-teamX" with your desired name
dig @ns1.cloud.ut.ee reddit-clone-teamx.cloud.ut.ee

# If ANSWER SECTION is empty (no IP), the name is available ✅
# If it shows an IP, the name is taken ❌ (choose another)
```

**Naming tips:**
- Use only lowercase letters (a-z) and numbers (0-9)
- No special characters or spaces
- Make it unique: `reddit-clone-team5`, `reddit-app-john`, etc.

### Step 2: Create the VM

1. **Log into ETAIS** (https://minu.etais.ee)

2. Click **"+ Add resource"** (left menu)

3. **Select Organization & Project:**
   - Organization: `DevOps course`
   - Project: `Your team's name`

4. **Choose VM offering:**
   - Scroll to **"Categories"** → **"VMs"**
   - Select **"Virtual machine in <VPC-name>"**

5. **Configure VM Settings:**

   | Setting | Value | Notes |
   |---------|-------|-------|
   | **Image** | `Ubuntu 22.04` or `CentOS 9` | Ubuntu recommended for beginners |
   | **Flavor** | `2 vCPU, 4GB RAM` | Your team has 4 cores, 8GB RAM total |
   | **System Volume Type** | `prod3 (IOPS intensive SSD)` | Fast storage |
   | **System Volume Size** | `20 GB` | For OS and applications |
   | **Data Volume Type** | `prod3 (IOPS intensive SSD)` | For database |
   | **Data Volume Size** | `10 GB` | For PostgreSQL data |
   | **SSH Public Key** | Select your key | The key you added earlier |
   | **Networks** | `<VPC-name>-sub-net` | Check "Auto-assign Floating IP" ✅ |
   | **Security Groups** | `default`, `ssh`, `ping` | Add these three |
   | **VM Name** | `reddit-clone-teamx` | Your unique name (lowercase only!) |
   | **Description** | `John Doe, Team X, DevOps 2025` | Your name, team, course |

6. **Review everything** and click **"Create"**

⏳ **Wait 2-3 minutes** for the VM to be created.

## 🔧 Part 8: Configure PostgreSQL

```bash
# Switch to postgres user
sudo -u postgres psql

# Now you're in PostgreSQL prompt (postgres=#)
# Create database and user:
```

In the PostgreSQL prompt, run:

```sql
-- Create a database for your app
CREATE DATABASE reddit_clone;

-- Create a user with password
CREATE USER reddit_user WITH PASSWORD 'your_secure_password_here';

-- Grant all privileges
GRANT ALL PRIVILEGES ON DATABASE reddit_clone TO reddit_user;

-- Grant schema privileges (PostgreSQL 15+)
\c reddit_clone
GRANT ALL ON SCHEMA public TO reddit_user;

-- Exit PostgreSQL
\q
```

### Configure PostgreSQL to accept connections:

```bash
# Edit PostgreSQL config
nano /etc/postgresql/14/main/postgresql.conf

# Find this line:
#listen_addresses = 'localhost'

# Change to:
listen_addresses = 'localhost'

# Save and exit (Ctrl+X, then Y, then Enter)

# Edit authentication config
nano /etc/postgresql/14/main/pg_hba.conf

# Find the line:
# local   all             all                                     peer

# Change to:
local   all             all                                     md5

# Save and exit

# Restart PostgreSQL
systemctl restart postgresql
```

**Note:** For CentOS, config files are at `/var/lib/pgsql/data/`

### Test the connection:

```bash
# Test connection
psql -U reddit_user -d reddit_clone -h localhost

# Enter password when prompted
# If you see: reddit_clone=>
# Success! Type \q to exit
```

## 🌐 Part 9: Install Web Server (Caddy - Recommended)

**Why Caddy?** It automatically handles SSL certificates (Let's Encrypt) - no manual configuration needed!

### Install Caddy:

```bash
# Add Caddy repository
apt install -y debian-keyring debian-archive-keyring apt-transport-https
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | tee /etc/apt/sources.list.d/caddy-stable.list

# Install Caddy
apt update
apt install -y caddy

# Check if Caddy is running
systemctl status caddy
```

### Alternative: Install Nginx

If you prefer Nginx:

```bash
# Install Nginx
apt install -y nginx

# Start and enable
systemctl start nginx
systemctl enable nginx

# Check status
systemctl status nginx
```

## 🔥 Part 10: Configure Firewall

```bash
# Enable UFW firewall
ufw --force enable

# Allow SSH (IMPORTANT - don't lock yourself out!)
ufw allow 22/tcp

# Allow HTTP
ufw allow 80/tcp

# Allow HTTPS
ufw allow 443/tcp

# Check firewall rules
ufw status

# Expected output:
# Status: active
# 
# To                         Action      From
# --                         ------      ----
# 22/tcp                     ALLOW       Anywhere
# 80/tcp                     ALLOW       Anywhere
# 443/tcp                     ALLOW       Anywhere
```

---

## 🔐 Part 11: Open Ports in ETAIS Security Groups

The firewall on the VM is now configured, but ETAIS also has its own firewall. Let's open the web ports:

1. Go to **ETAIS** → **Resources** → **VMs**
2. Find your VM → Click on it
3. Go to **"Networking"** tab → **"Security groups"**
4. Click **"Manage security groups"**
5. Click **"Create"**
   - **Name**: `web`
   - **Description**: `HTTP and HTTPS access`
   - Click **"Submit"**

6. Find the new `web` security group → Click **"Actions"** → **"Set rules"**
7. Click **"Add rule"** (for HTTP):
   - **Ethernet type**: `IPv4`
   - **Direction**: `Ingress`
   - **IP protocol**: `TCP`
   - **Destination port**: `80`
   - **Remote CIDR**: `0.0.0.0/0`
   - Click **"Submit"**

8. Click **"Add rule"** again (for HTTPS):
   - **Ethernet type**: `IPv4`
   - **Direction**: `Ingress`
   - **IP protocol**: `TCP`
   - **Destination port**: `443`
   - **Remote CIDR**: `0.0.0.0/0`
   - Click **"Submit"**

9. Go back to your VM → **"Networking"** → **"Security groups"**
10. Click **"Update Security groups"**
11. Add the `web` security group to your VM
12. Click **"Submit"**

## 🔑 Part 13: Set Up SSH Access for GitLab CI/CD

Now we need to create **another SSH key pair** specifically for GitLab to access your VM.

### On your VM (while connected via SSH):

```bash
# Generate a dedicated key for GitLab CI/CD
ssh-keygen -t rsa -b 4096 -C "gitlab-ci"

# Save to: /root/.ssh/gitlab_ci_rsa
# Press Enter for no passphrase (important for automation!)

# Add the public key to authorized_keys
cat /root/.ssh/gitlab_ci_rsa.pub >> /root/.ssh/authorized_keys

# Display the PRIVATE key (we'll need this for GitLab)
cat /root/.ssh/gitlab_ci_rsa
```

**📋 Copy the ENTIRE private key output**, including:
```
-----BEGIN OPENSSH PRIVATE KEY-----
...
-----END OPENSSH PRIVATE KEY-----
```

### Add Private Key to GitLab:

1. Go to your **GitLab project**
2. **Settings** → **CI/CD** → **Variables** → **Expand**
3. Click **"Add variable"**

**Variable 1: SSH Private Key**
   - **Key**: `SSH_PRIVATE_KEY`
   - **Value**: Paste the entire private key (including BEGIN and END lines)
   - **Type**: `File` ✅
   - **Protect variable**: ✅ (check)
   - **Mask variable**: ❌ (uncheck - keys can't be masked)
   - Click **"Add variable"**

**Variable 2: VM Host**
   - **Key**: `VM_HOST`
   - **Value**: `reddit-clone-teamx.cloud.ut.ee` (your VM's domain)
   - **Type**: `Variable`
   - **Protect variable**: ✅
   - **Mask variable**: ❌
   - Click **"Add variable"**

**Variable 3: VM User**
   - **Key**: `VM_USER`
   - **Value**: `root`
   - **Type**: `Variable`
   - **Protect variable**: ✅
   - **Mask variable**: ❌
   - Click **"Add variable"**

**Variable 4: Database Password**
   - **Key**: `DB_PASSWORD`
   - **Value**: `your_secure_password_here` (the one you set for PostgreSQL)
   - **Type**: `Variable`
   - **Protect variable**: ✅
   - **Mask variable**: ✅ (check - this is a secret!)
   - Click **"Add variable"**

## ✅ Part 14: Test SSH Connection from GitLab

Let's verify that GitLab can connect to your VM.

Add a test job to your `.gitlab-ci.yml`:

```yaml
stages:
  - build
  - test
  - deploy
  - verify  # New stage for testing

# ... (keep your existing build and test jobs)

# Test SSH connection
test-ssh-connection:
  stage: verify
  image: alpine:latest
  
  before_script:
    # Install SSH client
    - apk add --no-cache openssh-client
    
    # Set up SSH
    - eval $(ssh-agent -s)
    - chmod 400 "$SSH_PRIVATE_KEY"
    - ssh-add "$SSH_PRIVATE_KEY"
    - mkdir -p ~/.ssh
    - echo -e "Host *\n\tStrictHostKeyChecking no\n\n" > ~/.ssh/config
  
  script:
    - echo "Testing SSH connection to VM..."
    - ssh ${VM_USER}@${VM_HOST} "echo 'SSH connection successful!'"
    - ssh ${VM_USER}@${VM_HOST} "whoami"
    - ssh ${VM_USER}@${VM_HOST} "hostname"
    - ssh ${VM_USER}@${VM_HOST} "df -h"
  
  only:
    - main
```

Commit and push:

```bash
git add .gitlab-ci.yml
git commit -m "Add SSH connection test"
git push origin main
```

**Check GitLab pipeline:**
- Go to **CI/CD** → **Pipelines**
- Click on the latest pipeline
- Click on **test-ssh-connection** job
- You should see:
  ```
  SSH connection successful!
  root
  reddit-clone-teamx
  ```

✅ **If you see this, GitLab can successfully connect to your VM!**

## 🐛 Troubleshooting

### Issue 1: Can't SSH to VM

**Solution:**
```bash
# From your laptop:
ssh -v root@reddit-clone-teamx.cloud.ut.ee

# The -v flag shows debug info
# Check if:
# 1. VM is running in ETAIS
# 2. Security group 'ssh' is attached
# 3. Your public key is added to ETAIS
```

### Issue 2: GitLab can't connect to VM

**Checklist:**
- ✅ `SSH_PRIVATE_KEY` is added as **File** type in GitLab
- ✅ Private key includes `-----BEGIN` and `-----END` lines
- ✅ `VM_HOST` and `VM_USER` variables are set
- ✅ Public key is in `/root/.ssh/authorized_keys` on VM

### Issue 3: PostgreSQL won't start

**Solution:**
```bash
# Check logs
journalctl -u postgresql -n 50

# Check if port 5432 is free
netstat -tuln | grep 5432

# Reinitialize (careful - this erases data!)
# systemctl stop postgresql
# rm -rf /var/lib/postgresql/14/main
# postgresql-setup --initdb
# systemctl start postgresql
```

### Issue 4: Can't access VM from browser

**Checklist:**
- ✅ Security group `web` is attached in ETAIS
- ✅ UFW allows ports 80 and 443: `ufw status`
- ✅ Caddy is running: `systemctl status caddy`
- ✅ Try: `curl http://reddit-clone-teamx.cloud.ut.ee`
