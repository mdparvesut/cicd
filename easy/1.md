**Why this structure?**
- Keeps frontend and backend separated
- Easy to build each part independently
- Clear organization for the pipeline to understand

## 🔍 Part 4: Understanding GitLab CI/CD Pipeline

### What is a CI/CD Pipeline?

Think of it like an **automated assembly line** for your code:

1. **You push code** to GitLab
2. **GitLab Runner** (a worker machine) picks up your code
3. **Pipeline executes** predefined steps (build, test, deploy)
4. **Result**: Your app is automatically built and deployed

### Key Concepts:

**Pipeline**: A series of automated jobs that run when you push code

**Stages**: Groups of jobs that run in order:
- `build` stage: Compile/build your app
- `test` stage: Run tests
- `deploy` stage: Send code to VM

**Jobs**: Individual tasks within a stage (e.g., "build-frontend", "build-backend")

**Runner**: A machine that executes your pipeline jobs

**Artifacts**: Files produced by jobs (e.g., built React app, compiled Go binary) that can be passed to later stages

## 📝 Part 5: Create Your First `.gitlab-ci.yml` File

In your project root, create a file named `.gitlab-ci.yml`:

```yaml
# This is a GitLab CI/CD configuration file
# It defines what happens when you push code

# Define the stages (they run in this order)
stages:
  - build
  - test
  - deploy

# We'll use these variables across all jobs
variables:
  # Improve performance by disabling unnecessary features
  GIT_DEPTH: 1

###############################################
# BUILD STAGE
###############################################

# Job: Build Frontend (React + Vite)
build-frontend:
  stage: build
  image: node:18-alpine  # Use official Node.js Docker image
  
  script:
    # Go to frontend directory
    - cd frontend
    # Install dependencies
    - npm ci --cache .npm --prefer-offline
    # Build production bundle
    - npm run build
  
  # Save the built files to pass to deploy stage
  artifacts:
    paths:
      - frontend/dist/
    expire_in: 1 hour  # Keep artifacts for 1 hour
  
  # Cache node_modules to speed up future builds
  cache:
    key: frontend-dependencies
    paths:
      - frontend/.npm/
  
  # Only run on main branch and merge requests
  only:
    - main
    - merge_requests

# Job: Build Backend (Golang)
build-backend:
  stage: build
  image: golang:1.21-alpine  # Use official Go Docker image
  
  script:
    # Go to backend directory
    - cd backend
    # Download dependencies
    - go mod download
    # Build the binary (CGO disabled for static binary)
    - CGO_ENABLED=0 GOOS=linux go build -o reddit-clone-api ./cmd/api
  
  # Save the compiled binary to pass to deploy stage
  artifacts:
    paths:
      - backend/reddit-clone-api
    expire_in: 1 hour
  
  # Cache Go modules to speed up future builds
  cache:
    key: backend-dependencies
    paths:
      - /go/pkg/mod/
  
  only:
    - main
    - merge_requests

###############################################
# TEST STAGE (Placeholder for now)
###############################################

test-backend:
  stage: test
  image: golang:1.21-alpine
  
  script:
    - cd backend
    - go test ./... -v
  
  only:
    - main
    - merge_requests

###############################################
# DEPLOY STAGE (Placeholder - we'll complete in Step 4)
###############################################

deploy-to-vm:
  stage: deploy
  image: alpine:latest
  
  script:
    - echo "Deploy stage - we'll implement this in Step 4"
  
  only:
    - main
```

## 📖 Understanding the `.gitlab-ci.yml` File

Let me explain each part:

### 1. **Stages**
```yaml
stages:
  - build
  - test
  - deploy
```
These run **in order**. All `build` jobs complete before `test` jobs start.

### 2. **Image**
```yaml
image: node:18-alpine
```
This tells GitLab Runner to use a **Docker container** with Node.js 18 installed. It's like starting with a fresh computer that has Node already installed.

### 3. **Script**
```yaml
script:
  - cd frontend
  - npm ci
  - npm run build
```
These are **commands** that run in the container. Same as typing in terminal.

### 4. **Artifacts**
```yaml
artifacts:
  paths:
    - frontend/dist/
```
**Saves** the built files so the `deploy` stage can use them later.

### 5. **Cache**
```yaml
cache:
  key: frontend-dependencies
  paths:
    - frontend/.npm/
```
**Speeds up** future builds by saving `node_modules` between pipeline runs.

### 6. **Only**
```yaml
only:
  - main
```
Pipeline only runs when you push to the `main` branch.

## 🔧 Troubleshooting Common Issues

### Issue 1: "npm: command not found"
**Solution:** Make sure you're using `image: node:18-alpine` in the frontend job.

### Issue 2: "go: command not found"
**Solution:** Make sure you're using `image: golang:1.21-alpine` in the backend job.

### Issue 3: Pipeline doesn't start
**Solution:** Check that `.gitlab-ci.yml` is in the **root** of your repository (not inside frontend/ or backend/).

### Issue 4: "npm run build" fails
**Solution:** Make sure your `frontend/package.json` has a `"build"` script. Check your local build works first with `cd frontend && npm run build`.
