## 1. Understanding Separate Repository Architecture

### Why Two Separate Repositories?

```
Project Architecture:
├── reddit-clone-backend/     # Separate Git repository
│   ├── .gitlab-ci.yml        # Backend CI/CD pipeline
│   └── (Your Golang code)
│
└── reddit-clone-frontend/    # Separate Git repository
    ├── .gitlab-ci.yml        # Frontend CI/CD pipeline
    └── (Your React code)
```

**DevOps Benefits:**
- ✅ **Independent CI/CD pipelines**: Each service has its own build/test/deploy pipeline
- ✅ **Separate deployment cycles**: Deploy backend without touching frontend
- ✅ **Isolated secrets**: Backend secrets stay in backend repo only
- ✅ **Better security**: Principle of least privilege
- ✅ **Team autonomy**: Different teams can manage their own pipelines
- ✅ **Easier rollbacks**: Roll back one service without affecting others

## 5. Git Workflow and Branching Strategy

### 5.1 Branching Strategy Overview

```
main (production)
  ↓
develop (integration)
  ↓
feature/* (new features)
bugfix/* (bug fixes)
hotfix/* (emergency fixes)
```

**Branch purposes:**
- `main` - Production-ready code, always deployable
- `develop` - Integration branch, latest development
- `feature/*` - New features (e.g., `feature/authentication`)
- `bugfix/*` - Bug fixes (e.g., `bugfix/login-error`)
- `hotfix/*` - Emergency production fixes

### 5.2 Initial Branch Setup

```bash
# Create develop branch (do this for BOTH repos)
cd reddit-clone-backend

# Create develop branch from main
git checkout -b develop
git push origin develop

# Set develop as default branch in GitLab:
# Go to Settings → Repository → Default branch → develop
```

Repeat for frontend:
```bash
cd reddit-clone-frontend
git checkout -b develop
git push origin develop
```

### 5.3 Daily Git Workflow

#### **Starting a New Feature**

```bash
# Always start from latest develop
git checkout develop
git pull origin develop

# Create feature branch
git checkout -b feature/ci-cd-pipeline

# Verify you're on the right branch
git branch
# * feature/ci-cd-pipeline
#   develop
#   main
```

#### **Making Changes**

```bash
# Check what changed
git status

# Add files
git add .gitlab-ci.yml
git add scripts/deploy.sh

# Commit with descriptive message
git commit -m "ci: add initial CI/CD pipeline

- Add build stage for Golang backend
- Add test stage with coverage reporting
- Configure artifacts for build output"
```

#### **Commit Message Convention**

```
<type>: <subject>

<optional body>

<optional footer>
```

**Types for DevOps work:**
- `ci:` - CI/CD pipeline changes
- `build:` - Build system changes
- `chore:` - Maintenance tasks (dependencies, configs)
- `docs:` - Documentation updates
- `fix:` - Bug fixes
- `feat:` - New features
- `test:` - Adding tests

**Examples:**
```bash
git commit -m "ci: add deployment stage to pipeline"
git commit -m "build: update Dockerfile for multi-stage build"
git commit -m "chore: update .gitignore to exclude secrets"
git commit -m "docs: add deployment instructions to README"
```

#### **Pushing Changes**

```bash
# Push feature branch
git push origin feature/ci-cd-pipeline

# First time pushing? Set upstream:
git push --set-upstream origin feature/ci-cd-pipeline
```

#### **Creating Merge Request in GitLab**

1. Go to your GitLab repository
2. Click **"Create merge request"** banner (appears after push)
3. Fill in details:
   - **Title**: `ci: Add CI/CD pipeline`
   - **Description**: 
     ```
     ## Changes
     - Added .gitlab-ci.yml with build, test stages
     - Created deployment script
     - Added environment variable examples
     
     ## Testing
     - Pipeline runs successfully
     - Build artifacts are generated
     
     ## Related Issues
     Closes #1
     ```
   - **Source branch**: `feature/ci-cd-pipeline`
   - **Target branch**: `develop`
   - **Delete source branch when merged**: ✅
4. Click **"Create merge request"**

#### **After Merge**

```bash
# Switch back to develop
git checkout develop

# Pull latest changes (includes your merged feature)
git pull origin develop

# Delete local feature branch
git branch -d feature/ci-cd-pipeline
```

### 5.5 Handling Merge Conflicts

```bash

git checkout feature/your-feature
git pull origin develop

# If conflicts occur:
# Git marks conflicts in files like this:
<<<<<<< HEAD
Your changes here
=======
Changes from develop
>>>>>>> develop

# Fix conflicts manually in editor
# Then:

git commit -m "fix: resolve merge conflicts with develop"
git push origin feature/your-feature
```

### 5.6 Emergency Hotfix Workflow

```bash

git checkout -b hotfix/fix-deployment-script

# Create merge request to main (emergency)
# After merging to main, also merge to develop:
git checkout develop
git pull origin develop
git merge main
git push origin develop
```

## 7. Local Development Setup with Docker

### 7.1 Why Docker for Local Development?

**Benefits:**
- ✅ Consistent environment across team members
- ✅ Easy PostgreSQL setup (no manual installation)
- ✅ Quick teardown and rebuild
- ✅ Same setup works on Linux, Mac, Windows

### 7.2 Backend docker-compose.yml

Create `reddit-clone-backend/docker-compose.yml`:

```yaml
version: '3.8'

services:
  # PostgreSQL Database
  postgres:
    image: postgres:15-alpine
    container_name: reddit_clone_db
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${DB_USER:-postgres}
      POSTGRES_PASSWORD: ${DB_PASSWORD:-postgres}
      POSTGRES_DB: ${DB_NAME:-reddit_clone}
    ports:
      - "${DB_PORT:-5432}:5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${DB_USER:-postgres} -d ${DB_NAME:-reddit_clone}"]
      interval: 10s
      timeout: 5s
      retries: 5

volumes:
  postgres_data:
    driver: local
```

**Explanation:**
- `postgres:15-alpine` - Lightweight PostgreSQL image
- `${DB_USER:-postgres}` - Uses `.env` value or defaults to `postgres`
- `volumes` - Persists database data between restarts
- `healthcheck` - Ensures database is ready before connecting

### 7.3 Using Docker Compose

```bash
cd reddit-clone-backend

# Start PostgreSQL
docker-compose up -d

# Check if running
docker-compose ps

# View logs
docker-compose logs postgres

# Stop PostgreSQL
docker-compose down

# Stop and remove data
docker-compose down -v
```

### 7.4 Verify Database Connection

```bash
# Connect to PostgreSQL using psql (if installed)
psql -h localhost -U postgres -d reddit_clone

# Or connect using Docker
docker-compose exec postgres psql -U postgres -d reddit_clone

# Inside PostgreSQL shell:
\l                 # List databases
\dt                # List tables (after running migrations)
\q                 # Quit
```
